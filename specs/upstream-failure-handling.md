# 上游失败处理：冷却时刻、重放安全、实测成本

三个互相独立的小模块，都源自对同类项目的调研（见文末「来源」）。它们都在
**同一处**被用到——账号池的失败处理路径——所以放在一份文档里。

| 模块 | 文件 | 一句话 |
|---|---|---|
| 冷却时刻解析 | `admin/reset_at.py` | 上游明说了什么时候恢复，就别自己猜 |
| 重放安全分类 | `core/replay_policy.py` | 请求体已发出，就绝不重发 |
| 实测成本账本 | `admin/cost_ledger.py` | 按实测 credit 优先挑免费的号 |

---

## 1. 冷却时长要采信上游明示时刻

### 问题

`AccountPool.record()` 原本对所有失败一律用本地上界指数退避
（`base * 2^(fails-1)`，上限 2 小时）。这个猜测**必然不准**，两个方向都糟：

- **猜短了**：冷却窗口内账号被放回候选集，于是一次又一次撞同一堵墙。每次撞墙
  都是一次失败请求，也都是一次风控痕迹——越撞越糟。
- **猜长了**：健康账号被白扣几小时，额度用不掉。

### 做法

`admin/reset_at.py` 用三级来源解析上游**明说的**恢复时刻，按权威性排序：

1. **body 文案** —— `将在 2026-10-15 10:00:00 重置`。上游写给人看的，最权威、
   也最便宜（一次正则）。
2. **body 结构化字段** —— `data.resets_at` 等。上游不保证发。
3. **响应头** —— `Retry-After`（秒数或 HTTP-date）、`Retry-After-Ms`、
   `X-RateLimit-Reset`（epoch 秒或相对秒数，按数量级区分）。

三级都拿不到 → 返回 `None`，**回落本地退避**。绝不臆造一个「看起来正常」的
时刻——那会让排障时分不清「上游说的」和「我们猜的」。

两个必须写对的细节：

- **时区**：上游文案里的墙钟是 **UTC+8**。当成 UTC 解析会整体偏 8 小时，
  偏早等于冷却立刻到期（反复撞墙）、偏晚等于白扣半天，两种错都比「没有时间
  信息」更糟。所以显式固定 UTC+8，不交给运行环境时区。
- **拿到的时刻一律与本地退避取更晚者**，并夹在 24 小时以内。上游报到一天以后
  必然是脏数据，不能让它把账号永久扣住；而提前放出来只会在窗口内反复撞墙。

`last_error` 会写明用了哪个来源（`上游明示` / `本地退避`），排障时一眼能分清。

### 已验证

`tests/pool/test_reset_at.py` 24 例 + `tests/pool/test_account_pool.py` 5 例，覆盖时区、
相对量、HTTP-date、过期时刻（按「没有信息」处理而非「立刻恢复」，避免热循环）、
header 三种容器（`httpx.Headers` / ASGI bytes 字典 / 普通字典）、脏数据夹取。

## 2. 重放安全：请求体发出去之后绝不重试

### 问题

「失败就重试」在网关里**默认危险**：一次重放可能让上游把同一次生成计费两遍，
也可能让客户端收到重复输出。判别依据不是「失败了吗」，而是
**请求体有没有真的发出去**。

常见的错误做法是把所有 `httpx.HTTPError` 一律当「没发出去」重试。
`ReadTimeout` / `ReadError` / `RemoteProtocolError` 全都发生在请求体已发完
**之后**——上游很可能已经完整处理并计费，只是回程被掐断。

### 分类表

```
HTTP 状态码
  REPLAYABLE_STATUS    (401, 403, 429, 502, 503, 504)  换号重试有效
  DETERMINISTIC_STATUS (400, 404, 405, 413, 422)       换号也没用

传输异常
  REPLAYABLE_TRANSPORT (ConnectError, ConnectTimeout)  请求体未发出，安全
  WRITE_TIMEOUT        (WriteTimeout)                  可能已发出 → 默认不重放
  AMBIGUOUS_TRANSPORT  (ReadError, ReadTimeout, WriteError, RemoteProtocolError)
                                                       已发出、可能已计费 → 绝不重放
```

铁律：**Never replay after the upstream response opens.**

### 当前状态（重要）

**本项目现在没有任何上游传输异常的重试**——所有流式路径捕获 `httpx.HTTPError`
后直接回 502。所以这个模块目前**不改变任何行为**，它的作用是：

1. 把分类依据固定下来并写进日志（`explain()` 给出一句「为什么不重试」），
   排障时不用再猜某次 502 是不是重试过；
2. 让日后想加「失败换号」的人有个明确的判定入口，而不是顺手写出重复计费。

唯一存在的重试是 `PoolMiddleware` 里的**凭据准备失败**重试（`get_headers()`
抛错）——那发生在一个字节都没发给上游之前，明确安全，注释里已写明依据。

## 3. 实测成本账本

### 为什么需要「实测」

上游对不同账号在同一模型上的计费并不一致，而**是否收费无法从配置推断**：
限免额度、夜间免费、试用期只体现在响应里。模型注册表里的静态倍率
（`x0.79`）只是标价，不是这个账号实际被扣的钱。

结果是同一个请求走不同的号，成本可能差几倍。所以按 `(账号, 模型)` 记录
**观测到的**单价，选号时优先挑实测免费的。

### 关键纪律：观测不到就什么都不做

本项目的真实约束是——**我们尚未确认上游到底发不发 `credit` 字段**。
（当前代码里 `usage` 只有 token 计数，没有任何地方读到过 credit。）

所以账本被刻意设计成「不观测就不生效」：

- 只有响应里真的带回了可解析的 credit 数值，才写入账本；
- 账本为空（或该模型没有任何免费观测）时，`prefer_free()` **原样返回候选**，
  选号行为与加这个功能之前完全一致。

即使上游从不发 credit，这个模块也是零行为变化的安全赘物，而不是一个悄悄
改变选号逻辑的黑盒。

### 语义细节

- **「未知」不等于「收费」**。`is_free()` 对未观测的账号返回 `None` 而不是
  `False`：未知号在有免费号时被让开，但没有免费号时仍正常参与轮转——
  否则新加的账号永远等不到第一次观测。
- **观测有 6 小时有效期**。优惠是时段性的：夜间免费的号到了白天照常收费，
  拿夜间观测指导白天选号会把成本算反。
- **EMA 平滑**（α=0.3）。单次请求的抖动不该立刻改变对账号的判断。
- **字段名逐个试、试不到就放弃**（`credit` / `credits` / `total_credit` /
  `credit_used` / `cost`）。宁可账本为空，也不能猜一个值——猜错会把流量
  全压到一个其实收费的号上。

### 怎么知道它有没有在工作

`overview` 的 `metrics.cost_ledger` 透出 `{entries, active, observed, skipped}`。
**`observed` 长期为 0 就说明上游不发 credit**，账本全程是空转的安全状态。
这是判断该功能是否真的生效的唯一依据。
