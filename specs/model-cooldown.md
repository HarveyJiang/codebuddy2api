# 模型级冷却（单个模型限流不冷却整个账号）

用户 2026-10-20 明确要求：**不能因为单个模型被限流就把整个账号冷掉**。

## 一、为什么改

上游的限流绝大多数是**按模型**的。实测文案长这样：

> 当前您在 Step-5-Preview 模型的使用量已超出频率限制，可在 2026-10-18 14:23:36 重置后使用。

同一个账号换个模型照样能用。但改造前 `AccountPool.record()` 不管哪个模型撞了限流，
冷却都写在账号上（`account_status[aid].cooldown_until`），于是：

- 冷却 10 分钟里，这个号**所有**模型都不可用；
- 池子里等于少了一个人，别人替它挨同样的限流；
- 用户只能等，或者手动点「解除冷却」——那正是 2026-10-18 加这个按钮的原因。

## 二、判定表

| 上游情况 | HTTP | 落点 | 账号被冷却？ | 冷却时长 |
|---|---|---|---|---|
| 模型限流 / 过载 | 429、503 | `model_cooldowns[model]` | **否** | 上游明示恢复时刻（夹在 60s~24h）；拿不到则本地退避 5min→2h |
| 后端声明的 soft 码（如 Trae 404「模型不存在」） | 后端自带表 | `model_cooldowns[model]` | **否** | 后端声明值（Trae = 600s） |
| 认证 / 权限被拒 | 401、403 | `cooldown_until`（账号级） | 是 | 指数退避 5min→2h，采信上游时刻时取**更晚**者 |
| 账号额度耗尽 | 402 | `cooldown_until`（账号级） | 是 | 指数退避 30min→2h，并触发积分重查 |
| 容量排队（queue） | 429/503 + 排队特征码 | `queued_until`（让位） | 否 | `queue_cooldown`（默认 120s） |
| 成功 | 2xx | 清 `model_fails` / `consecutive_fails` | 否 | — |

**判不准就退回账号级**：拿不到模型名时（老调用方、旧数据、异常路径）无法判定
影响范围，此时按旧行为冷却整个账号 —— 宁可多冷一个号，也不要让请求在同一个
限流模型上反复撞墙（每次都是一次风控痕迹）。

## 三、数据结构

`account_status[aid]` 新增两个字段（都是 JSON 值，落在同一行的 status JSON 里）：

- `model_cooldowns`: `{模型名: 截止时间戳}` —— 该账号各模型的冷却截止时刻；
- `model_fails`: `{模型名: 连续失败次数}` —— 模型级退避的计数，成功即清。

两者都**只增不减地延长**冷却（并发响应乱序时不能把已有冷却改早）。

## 四、影响到的路径

| 位置 | 改动 |
|---|---|
| `AccountPool.record()` | 按上表分流；模型级只写 `model_cooldowns`，不动 `cooldown_until` |
| `AccountPool.select()` | 候选集用 `usable_for(row, model)`：账号级可用 **且** 该模型没在冷却 |
| `AccountPool.state()` | **不**因模型级冷却改成 cooling —— 账号仍是可用账号 |
| `AccountPool.rows()` | 暴露 `model_cooldowns`（只含未过期项）与 `model_cooling_count` |
| `AccountPool.operate(clear-cooldown)` | 账号级 + 模型级冷却一起清 |
| `PoolMiddleware` | 记 `record()` 时传实际用的模型（`attempt_model`） |

选号失败时的报错也分两种：池子空了报「暂无可用账号」，**只是这个模型全在冷却**
报「模型 X 在全部可用账号上都在冷却，请换模型或稍后重试」—— 后者让人知道
换模型就能用，不必去查登录态。

## 五、前端

- 账号行状态列加一条备注：`模型冷却 N 个：<模型> 至 <时间>`，并注明「只影响这些
  模型，账号本身仍参与分配」。
- 账号详情弹框加「模型冷却」分组，逐个列出模型与恢复时刻。
- 「解除冷却」按钮在**账号冷却或模型冷却**时都出现。

## 六、边界

- 401/403/402 依旧是账号级：凭据失效、权限被拒、额度耗尽换模型也救不了。
- Trae 的 404 是**模型级**（模型不存在 ≠ 账号坏了），所以 Trae 账号在某个模型上
  撞 404 后，别的模型照常可用。
- 排队让位（`queued_until`）本来就是「优先跳过」语义，与模型级冷却互不影响。
